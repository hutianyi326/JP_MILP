## 普通成交 CSV 的字段语义

### 区域轴、量价单位和记录粒度

CSV 的前三类结构如下：

```text
H,電力需給調整力取引所取引結果,対象年月,商品区分,ブロック数
P,確報値,YYYYMM,产品名,8 或 48
TT,調達区分,交易信息,北海道,東北,東京,中部,北陸,関西,中国,四国,九州,合計
```

E58 第 962、975、988、1105、1118 行明确给出以下轴：

- `募集量（TSO別）[MW]`、`落札量合計（TSO別）[MW]` 的九个区域列是 TSO 区域。
- `応札量合計（電源属地別）[MW]`、`落札量合計（電源属地別）[MW]` 及相应件数/价格的九个区域列是电源属地（发电资源所在地）区域。
- 两类区域不能互换，也不能把同一行的九列当成“九个电源类型”。`合計`是该行的汇总列，不是第十个区域。
- 普通结果中的数量和容量字段按文件标签使用 MW；价格按 `[円/kW・30分]` 使用。E58 第 1134 行另说明最高、最低、平均落札价格不含消费税。

每个记录键形如 `YYYYMMDD Bnn` 的无分隔形式，例如 `20240401B04`。日期是键的前八位，块号是 `B` 后两位。CSV 文件名中的 `202503` 或 `202603` 只能作候选月份，不能代替记录键日期。

E58 第 299–360 行给出的时间映射为：

- `ブロック数=8`：`B01` 至 `B08`，每天 8 个连续三小时块。
- `ブロック数=48`：每天 48 个连续三十分钟块。页面界面以 `B01-1` 至 `B08-6` 展示，CSV 将其展平为 `B01` 至 `B48`；展平索引为 `6 × (三小时块序号 - 1) + 半小时子块序号`。

`P` 行的块数是每个文件的结构判据。不能因为文件属于三次②或某一年度，就强行把全部文件转换为 8 块或 48 块。

### 「系统／追加／合计（确报）」不是可直接相加的三份容量

普通结果的每个日期-块通常包含 39 行：

1. `システム約定結果`（系统约定结果）13 行；
2. `追加調達結果`（追加调达结果）13 行；
3. `合計（確報値）`（合计/确报值）13 行。

系统行的成交量和价格字段多用 `落札...`，追加和合计行多用 `約定...`。`合計（確報値）`是 EPRX 已发布的总结果，应作为独立的官方聚合字段读取；不能把系统行和追加行逐格相加来重建它。一个可复算的反例在 `EA24C_db53d2bab623.zip/202404_4-0_result.csv`：

- `20240401B04`，字段 `落札量合計（電源属地別）[MW]`，系统行 CSV 第 123 行的東京值为 `576.681`；
- 同一键、字段 `約定量合計（電源属地別）[MW]`，追加行第 136 行的東京值为 `0`；
- 合计/确报行第 149 行的東京值为 `124.681`，并非 `576.681 + 0`。

同一例中，追加结果的 `募集量（TSO別）[MW]` 为 `-`，这表示该分类下不适用/无发布值，不能在解析时静默改成数值 0。规则如下：

- 研究“全部已确认成交量”时直接读取 `合計（確報値）` 的 `約定量合計...`；
- 研究系统或追加流程时分别读取各自的行；
- 不把三类行纵向去重后再加总，也不把价格的最高、最低、平均值相加或简单平均；
- 对量/件数行可用九个区域数值重算 `合計` 作完整性检查；对价格行保留 EPRX 报出的区域值和总值，不自行重构权重。

这一区分同时解释了为什么主研究中“确报总量”和“系统/追加”必须作为不同的分类维度存储。

### 正确筛选规则

实现时按以下顺序处理：

```text
1. 用 cp932 解码；先读 H/P/TT，再读记录键以 YYYYMMDDBnn 识别数据行。
2. actual_date = 记录键[0:8]；block_no = 记录键中 B 后的两位整数。
3. 以 P[4] 判定当日结构：8 -> B01..B08；48 -> B01..B48。
4. 若文件名含 0301-0313，只保留 actual_date <= 当月 13 日；
   若文件名含 0314-0331，只保留 actual_date >= 当月 14 日。
5. 普通月档按 actual_date 落入目标月份后保留；不要按 ZIP 年度标签直接截取。
6. 只删除分档文件中落在另一分档区间的跨期填充；有效区间内的 0 和 '-' 保留。
7. 量和件数字段将九区域列与合计列分开保存；价格字段保留原始汇总，不做列加总。
```

若将块转成长表，8 块文件的时间戳为 `00:00, 03:00, ..., 21:00`；48 块文件的时间戳为 `00:00, 00:30, ..., 23:30`。不要因为两个分档文件都含有同一日期键，就把 8 块行和 48 块行拼成同一日的 56 个块；先按实际日期和 `P` 结构过滤，再按产品规则选择相应结构。

## 2026 年确报与速報的边界

本地 `EA26*` 确报包只包含 2026-04 至 2026-07。E58 第 1707–1718 行明确将 2026-07 确报的公告日期列为 2026-08-25；页面的速報表（第 1458 行起）另列 2026 年度 `*_prompt.zip`。研究期要求覆盖至 2026-08-31，因此应建立独立的 `result_status` 字段：

- `確報`：2025-01-01 至 2026-07-31 可使用相应年度的 `_result.zip`；
- `速報`：2026-08-01 至 2026-08-31 使用官方 `*_prompt.zip`，保持原状态；
- 不用 2026-08 的速報补写成确报，也不以确报缺档为理由删除 8 月观察值。

同一日期若同时有速報和后续确报，两个版本应按状态分别留存；回测/区域比较必须显式选择版本，避免一条时间序列混入两种发布日期状态。
